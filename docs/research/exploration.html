Exploration report · 1 November 2026 · working name “Holdfast”

A reminder system that won’t let a commitment slip

Feasible · no hard blocker for the MVPAndroid + Ubuntu GNOME 50 Wayland first. iOS, Windows and macOS later, from the same code.

Every surface you asked for can be built today: phone reminders, home-screen widgets, a PC tray and global shortcut, calendars and notifications. The difficulty sits in one place, reminders that always fire. On Android that needs a native exact-alarm engine that survives Doze, reboots and battery killers. On Linux it needs a resident scheduler, because the OS has no scheduled-notification store.

Product vision

Capture in one breath, tie it to a real moment, keep it moving until done

“A local-first reminder system that never lets a commitment slip: capture it in one breath, attach it to the real-life moment you’ll act on it, and let an honest, calendar-aware plan, and your AI agents, keep it moving until it’s done.”
Signature 1 · Moments

Cues that won’t let go

Any task can carry a Moment: a time, a place (arrive or leave), a device (the car or your headphones connect), driving start/stop, or a PC event like login or the start of the workday. If you don’t act, the reminder escalates: a gentle ping, then a repeat in a different sound and style, then an opt-in full-screen alarm. When you snooze the same task again and again, it asks “break it down, move it, or drop it?”.

Why it works: “when X, do Y” plans raise goal attainment (d ≈ 0.27–0.66), and alerts that vary resist habituation. Bluetooth connect events can wake a killed Android app.
Signature 2 · Honest Day

Brain dump → a plan that knows you

Speak or paste a messy paragraph. The AI returns tasks, durations and sub-steps as a diff you approve. The planner then builds today around your calendars, using your own estimate-versus-actual history (“you usually take 1.5× on #admin”), and re-flows the day when you slip. A morning plan and an evening shutdown close the loop.

Why it works: correcting the planning fallacy with your past data, and concrete plans quiet the nagging of unfinished goals. No competitor found calibrates against personal history.
Signature 3 · Agent-native, local-first

Your data, your agents

The data lives in on-device SQLite and works fully offline, with optional end-to-end encryption per project. The backend is your own Docker stack. A local MCP server ships with the Ubuntu app so Claude Code can add, query, complete and plan tasks.

To be precise: MCP alone is table stakes now, since Todoist and Super Productivity have it. What sets this app apart is the combination of GNOME depth, tested reliability and a private agent interface.

The gap Holdfast fills

  • Reminder reliability as a tested guarantee on Android, with OEM guidance, a self-test and a late-fire log.
  • Native-feeling GNOME Wayland integration: portal hotkey, tray, reminders with the app closed, a CLI.
  • True multi-provider two-way sync running on your server, so a home Nextcloud behind NAT works (Morgen can’t do this).
  • Evidence-based cues and nagging instead of plain time reminders.
  • Local-first data + a private agent interface at an individual’s price.

Market signals worth knowing

  • Clockwise shut down on 2026-03-27 and deleted user data. Planners pivot and close, so export and portability matter.
  • AI planners charge $15–34/month. A €3–4/month “Sync & AI” tier would undercut every one of them.
  • Tasks.org proves Kotlin Multiplatform works for exactly this app class, and its desktop is leaving alpha. It is the closest open-source competitor to watch.

Why Flutter wins

  • Linux desktop is a day-one platform, and Flutter’s Linux pieces exist today: hotkey_manager speaks the GlobalShortcuts portal, tray_manager does SNI over D-Bus, and PowerSync supports Flutter Linux. With KMP you would write the D-Bus tray, notification and portal client yourself.
  • The hybrid removes Flutter’s Android weakness. Widgets are native Glance code in every framework, and the alarm engine is best written in Kotlin anyway.
  • One language end to end (Dart for UI, domain, DB codegen, sync and even the API server) plus hot reload suits solo work with an AI agent.
  • It’s already in your stack: Flutter 3.47.9 and FVM 4.3.2 are pinned in /stack/.env.

Why it might not, the real risks

  • Several key plugins have a single maintainer (home_widget, receive_sharing_intent); system_tray is abandoned.
  • Linux has no scheduled notifications in the plugin, so you own the scheduler.
  • Desktop multi-window is experimental, so the quick-add popup needs a workaround.
  • Flutter 3.50 (November) deprecates the in-SDK Material library. Start on material_ui from day one.
  • Runner-up: pick KMP + Compose if Android, Wear and widgets are the product and the Linux desktop is secondary. Tasks.org proves it works.
  • Optional tie-breaker: a 2-day KMP Linux spike run next to Flutter spike S2.

The scores are judgement calls grounded in verified facts. If KMP gets the same “in-repo native module” credit on Linux that Flutter gets on Android, its weighted score rises to about 82.5, still 3 points behind.

Architecture

Devices own the reminders. The server only syncs and bridges.

The rule that shapes everything: a reminder must fire with zero network. Push messages only wake a device so it syncs and re-arms. The app’s own database is the source of truth, and Google, Microsoft and CalDAV are adapters.

How an Android reminder survives everything

StoreReminders and expanded recurrences live in SQLite, not in the OS.
ArmrescheduleAll() arms the next ~48 h (≤ 50 alarms) with setAlarmClock, idempotently.
Re-arm on everythingBoot, app update, time/zone change, permission grant, every app start, every sync.
Fire + actNotification with Done / Snooze / Tomorrow. The action applies without starting Flutter.
Escalate + proveNo action → re-arm at 5 / 10 / 20 min with varied sound. A self-test logs lateness.

Data model essentials

  • UUIDv7 IDs minted on the device; soft-delete tombstones; a server-bumped version.
  • tasks carry an RFC 5545 RRULE plus a “repeat after completion” mode. Completing one instance writes an override row and never mutates the series.
  • moments hold the if-then cues; reminders map 1:1 to VALARM.
  • reminder_deliveries gives cross-device dedupe and the late-fire log.
  • Wall-clock times are stored as local time + IANA zone (never UTC), so DST and travel behave. Tests cover Paris, New York and Lord Howe (a 30-minute DST shift).

Sync, AI and privacy

  • Field-level last-writer-wins, with domain rules: completion beats a concurrent edit, delete beats edits.
  • Exit ramp if PowerSync changes: your data is in your Postgres and the client is plain SQLite. Fallbacks are sqlite-sync or a hand-rolled outbox (2–4 weeks).
  • AI goes deterministic grammar first, then on-device Gemini Nano, then Claude Haiku 5.5 through your proxy, always shown as a preview before saving.
  • Optional per-project E2EE (libsodium). Encrypted projects skip the calendar bridge and server AI, and the UI says so.
  • The local MCP server confirms destructive tools and keeps an audit log, which guards against prompt-injected agent actions.
