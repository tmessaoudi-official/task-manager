## C. Deprecations / policy changes found

1. **MCP 2026-07-28 deprecates Dynamic Client Registration, Roots, Sampling, Logging and HTTP+SSE**, and removes the `initialize` handshake and sessions. Any remote-MCP plan must target Client ID Metadata Documents and the stateless model.
2. **Gemini 2.5 Flash-Lite**: closed to new Gemini API users (the deprecations page I fetched says so). On Google Cloud its retirement was announced for 2026-10-20, but I did not confirm it happened. Use 3.5 Flash-Lite.
3. **Claude Haiku 3.5 is retired**, and Sonnet 4.5 is marked deprecated on the pricing page. This is not used by the report, but the cost model must pin a current model ID.
4. **Live Updates usage policy** excludes upcoming calendar events and alerts. That rules out a persistent "next commitment countdown" in ranked feature #9. A short "about to start" window is a grey area.
5. **Play location rules for Android 17 (API 37+), from 2027-01-27**: the Android location button for one-time/infrequent location requests. This is relevant to geofence onboarding. I did not check whether geofencing counts as "infrequent".
6. **Inexact fallback**: a developer PR (secondary) reports that an alarm set without exact access stays inexact even after the user grants the permission, so the app must reschedule on `SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED`. That is unverified in official docs.
7. **Android 17 background-audio restriction on reminders** (one developer report, secondary): an inexact reminder posted from a background worker played no sound when the ringer was muted. Unverified. Re-check the Android 17 behaviour-change page before building the nag tiers.

## D. Missing angles

- **OEM background killers** (Xiaomi, Samsung, OnePlus, …) and the battery-optimisation exemption flow (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, itself Play-restricted). These cause more missed reminders than AOSP policy does, and the report mentions them only as a "long tail".
- **Notification runtime permission** (`POST_NOTIFICATIONS`, Android 13+) and channel design are prerequisites for every reminder feature, and the report does not cover them.
- **Wear OS / watch delivery**: an unmissable nag usually lands on the wrist. Not covered.
- **The cross-platform framework's reach into these APIs**: AlarmManager, full-screen intents, manifest receivers, Live Updates and ML Kit GenAI are all native Android APIs. Whether Flutter/KMP/RN plugins expose them, or require platform channels, decides the effort numbers. The report gives effort figures without naming that dependency.
- **Ubuntu notifications for a nag tier**: GNOME notification urgency and actions, and whether a sandboxed (Flatpak/Snap) app can use background/autostart portals. Not checked.
- **Google OAuth verification** for calendar scopes (flagged as open). Also Microsoft Graph and CalDAV integrations are absent from the innovation ranking, although two-way sync is the precondition for #6/#7.
- **AI privacy/compliance**: sending brain dumps to a cloud LLM means data processing terms and GDPR (the user is in Europe/Paris). Not covered.
- **MCP security**: a local stdio MCP that can *write* tasks is exposed to prompt-injection-driven actions. The spec's tool-safety section requires consent UI. Not covered.
- **Evidence-quality caveat**: most E-rows are verified only through secondary sources. The ranking weights (E1 especially) should be discounted to the d=.27–.66 range.
