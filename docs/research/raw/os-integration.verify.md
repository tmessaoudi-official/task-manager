# Adversarial verification of os-integration.md (2026-11-01)

Method: each load-bearing claim was re-checked with WebFetch of the primary source, plus WebSearch (extended) for policy, version and status claims. Local claims were re-probed on the user's machine with `busctl`, `dpkg -l` and `gnome-extensions info`.

Verdicts: **confirmed**, **partly-wrong** (the core holds, but a detail or citation is wrong), **refuted**, **could-not-check**. Grades follow the same scheme: verified, inferred or unverified.

## 3. Deprecations / status changes found

- Microsoft Graph `baseTask` (old Tasks API) is **deprecated**. Use `todoTask`. [verified: subscription page]
- Glance `glance-wear-tiles` is **deprecated** in favour of `androidx.glance.wear` (wear widgets). [verified]
- Graph: subscription lifetimes beyond the maximum "will fail" in the future, so clamp the expiry on the client. [verified]
- Google Play's target-API-36 extension window closes 2026-11-01. [inferred]
- No deprecation found for: SCHEDULE_EXACT_ALARM, setAlarmClock, Google Tasks API, Google CalDAV, the GlobalShortcuts portal or the AppIndicator extension (open bug, not abandoned).
- flutter_local_notifications 22.3.3 (published about a week ago, verified publisher dexterx.dev) is **maintained, not deprecated**. It **does not support scheduled notifications on Linux** ("lack of a scheduler API"). It exposes `AndroidScheduleMode`, `requestExactAlarmsPermission()` and `requestFullScreenIntentPermission()`. [verified: https://pub.dev/packages/flutter_local_notifications]

## 4. Important angles the report missed

1. **Android developer verification (sideloading).** Enforcement started on 2026-09-30 in Brazil, Indonesia, Singapore and Thailand, on certified devices running Android 7+, and expands globally in 2027. France and the EU are not in phase 1. A free "limited distribution" account covers up to 20 devices with no ID and no fee. An "advanced flow" lets power users install unverified apps. Whether ADB installs are exempt is **not stated** on the official page. This matters for a personal-APK and F-Droid distribution plan in 2027. [verified: https://developer.android.com/developer-verification ; ADB exemption = could-not-check]
2. **USE_EXACT_ALARM eligibility through the calendar feature** (see claim 1). The app shows calendar event notifications, which could qualify it. Play reviewers decide this case by case. [inferred]
3. **xdp 1.21.0 also needs an AppID for portal autostart** (RequestBackground). Unsandboxed .deb builds need a resolvable .desktop app-id for both the global shortcut and autostart, or they fall back to `~/.config/autostart`. [verified: NEWS]
4. **Which Calendar scopes are sensitive was never established.** The report recommends `calendar.app.created` as the narrowest scope but does not check whether it avoids sensitive-scope verification. [could-not-check]
5. **The Flutter plugin layer for Linux integration was not assessed.** The report gives no maintenance or Wayland status for tray (`tray_manager`/`system_tray`), global hotkeys (`hotkey_manager`, X11-only?), single-instance or portal bindings. The GNOME section rests on OS facts only. [could-not-check, not fetched]
6. **flutter_local_notifications cannot schedule on Linux.** This confirms that a background daemon or systemd-timer design is needed on desktop, whichever UI framework is chosen. [verified]
7. **Google Tasks `assignmentInfo` and assigned tasks.** Tasks assigned from Docs or Chat appear in the API, and the sync must handle them. [verified: Tasks reference]
8. **Exact-alarm denial after backup-and-restore** and pre-grant on device upgrade. The report mentions backup/restore but not the upgrade pre-grant. A test matrix should cover fresh install, restore and upgrade. [verified]
9. **Real-world check of production-unverified token lifetime.** Google publishes nothing on it. Put a 7-day refresh test into the M1 acceptance criteria. [inferred]
10. **Microsoft national clouds:** todoTask webhooks are not available there. This is minor for a personal app. [verified]

## 5. Summary

The report's core architecture inputs hold:
- exact alarms need user consent;
- Google Tasks cannot carry times;
- Google CalDAV has no tasks;
- iCloud Reminders are reachable only on Apple devices;
- the Microsoft To Do model is rich;
- the GNOME tray is fragile;
- the GlobalShortcuts portal needs an AppID;
- iOS caps pending notifications at 64.

Errors are in detail and citation:
- the target versus device version wording;
- the revocation citation;
- the claim that ConfigureShortcuts is missing (it is exposed locally);
- the "soonest-firing kept" rule (unsupported);
- the token lifetime of "In production, unverified" apps (undocumented);
- the sensitivity of each Calendar scope (unknown);
- the narrower scope of bug #628;
- the overstated background-audio rule.

The two biggest omissions are Android developer verification and the Flutter Linux plugin layer.
