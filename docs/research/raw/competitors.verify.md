# Adversarial verification of competitors.md (2026-11-01)

Method: I re-fetched the primary sources cited for each load-bearing claim, searched for 2026 policy changes, and queried the GitHub API with curl and jq for release dates and release-note bodies.

Grades used below:
- **verified**: I fetched or searched the source myself, and the URL is given.
- **inferred**: reasoned from verified facts.
- **unverified**: I could not check it.

## Deprecations and changes found

1. **`USE_EXACT_ALARM` is not usable by a to-do app on Play.** It is limited to alarm/timer and calendar-event apps (Play policy 13986130).
2. **`USE_FULL_SCREEN_INTENT` is not auto-granted** to non-alarm, non-calling apps on Android 14 and later, and is reviewed on Play. A "nag me full-screen" reminder needs a runtime user grant.
3. **Android 16 JobScheduler/WorkManager quota enforcement**, even for active-bucket and foreground-service-concurrent jobs. Background calendar sync must tolerate being stopped (`getStopReason()`). `setImportantWhileForeground` is now ignored.
4. **Android 17 memory limiter** kills apps over RAM-based limits, and adds background-audio foreground-service while-in-use rules (an exact-alarm exemption applies for `USAGE_ALARM`).
5. **Geofencing removed as an approved foreground-service use case** (Play, effective 2027-01-27). This affects the design of location reminders (G11).
6. **Planner iCal feed retired** (early 2026). **Clockwise shut down** (2026-03-27).
7. **The Doist MCP repository moved**: the original todoist-mcp repo is deprecated in favour of Doist/todoist-ai (3p, via search).
8. Morgen: Nextcloud is tested for sync but not supported by AI Workflows (its own guide, table dated Nov 2025). This is not a deprecation.

## Angles the report missed

- **Tasks.org is the most dangerous open-source competitor, and it is built on KMP plus Compose Multiplatform** with Android, desktop (Linux x64/arm64) and iOS targets. This is real-world evidence for the framework decision (KMP/CMP is viable for exactly this app class), and it shows the gap may close.
- **Super Productivity already covers Android and Linux with Google multi-account calendars, CalDAV and local MCP** (Capacitor plus Electron). The differentiation has to come from native integration and reliability, not from coverage.
- **Todoist's official MCP** is missing from the MCP list. It is the market leader, so this reinforces that "MCP is table stakes".
- **Server-side versus on-device calendar sync.** Morgen requires the CalDAV server to be publicly reachable from its servers, which suggests cloud-side sync, so a home Nextcloud behind NAT would fail (inferred). On-device sync (like DAVx5 or Tasks.org) is a real differentiator for self-hosters.
- **Provider API costs and compliance for a public product.** These were not covered: Google OAuth app verification for the Calendar and Tasks scopes, Microsoft publisher verification and admin consent, and iCloud app-specific passwords for CalDAV. They are not verified here and belong in the integration dive.
- **The Android-side open-source CalDAV ecosystem** (DAVx5, jtx Board, Fossify Calendar, OpenTasks) was not surveyed. The user's app could interoperate with the Android CalendarContract/tasks providers instead of reimplementing CalDAV (unverified, not checked).
- **The play-policy-safe reminder strategy**: `SCHEDULE_EXACT_ALARM` onboarding, the `canScheduleExactAlarms()` check, `ACTION_SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED` rescheduling, and a `setWindow()` fallback, all from the verified Android docs. That is the concrete form of the "reliability as a guarantee" wedge (G5).
- **Timed-task sync asymmetry.** Graph To Do carries reminders, while Google Tasks cannot. The report's G4 is correct, but it should say explicitly that **Microsoft To Do is a viable two-way timed-task target and Google Tasks is not**.
